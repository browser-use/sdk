A US residential proxy is enabled by default. The browser's traffic passes
through that residential IP before reaching the website, so the website sees
the proxy's location—not your server's.

Set `browser_settings` / `browserSettings` when you create a V4 run to choose
another country:

<Note>
  The current TypeScript SDK type requires `proxyCountryCode` whenever
  `browserSettings` is present. Use `"us"` to keep the default, or `null` to
  disable the managed proxy.
</Note>

<CodeGroup>
```python Python
from browser_use_sdk.v4 import BrowserUse

client = BrowserUse()
run = client.runs.create(
    "Get the iPhone 16 price on amazon.de",
    browser_settings={"proxyCountryCode": "de"},
)
```
```typescript TypeScript
import { BrowserUse } from "browser-use-sdk/v4";

const client = new BrowserUse();
const run = await client.runs.create({
  task: "Get the iPhone 16 price on amazon.de",
  model: "gpt-5.6-luna",
  modelParams: { reasoning: { effort: "xhigh" } },
  browserSettings: { proxyCountryCode: "de" },
});
```
```bash curl
curl https://api.browser-use.com/api/v4/runs \
  -H "X-Browser-Use-API-Key: $BROWSER_USE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"task":"Get the iPhone 16 price on amazon.de",
       "browserSettings":{"proxyCountryCode":"de"}}'
```
</CodeGroup>

## Disable proxies

Pass `null` for QA or internal sites that do not need a residential proxy:

<CodeGroup>
```python Python
run = client.runs.create(
    "Test my staging site",
    browser_settings={"proxyCountryCode": None},
)
```
```typescript TypeScript
const run = await client.runs.create({
  task: "Test my staging site",
  model: "gpt-5.6-luna",
  modelParams: { reasoning: { effort: "xhigh" } },
  browserSettings: { proxyCountryCode: null },
});
```
</CodeGroup>

## Custom proxy

Custom proxies are available to all accounts, including free and pay-as-you-go
accounts. No subscription is required. Normal credit, spend, and concurrency
limits still apply.

The request format depends on what you are creating:

| REST endpoint | Custom proxy field |
| --- | --- |
| `POST /api/v4/browsers` | Top-level `customProxy` |
| `POST /api/v4/runs` | `browserSettings.customProxy` |

`browser_settings` is the Python SDK keyword for agent runs. In REST JSON,
the agent-run field is `browserSettings`.

### Standalone browsers

For a browser you control with Playwright, Puppeteer, or another CDP client,
put `customProxy` directly in the request body:

```bash curl
curl https://api.browser-use.com/api/v4/browsers \
  -H "X-Browser-Use-API-Key: $BROWSER_USE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "customProxy": {
      "host": "proxy.example.com",
      "port": 8080,
      "username": "YOUR_PROXY_USERNAME",
      "password": "YOUR_PROXY_PASSWORD"
    }
  }'
```

Replace the proxy details with yours. Omit both `username` and `password` if
your proxy does not require authentication. Do not wrap these settings in
`browserSettings` or `browser_settings` on `/api/v4/browsers`.

Keep the returned browser ID and stop the browser with
`PATCH /api/v4/browsers/{id}` and `{"action":"stop"}` when finished. See the
[Create browser reference](/cloud/api-v4/browsers/create-browser-session) and
[Browser quickstart](/cloud/browser/quickstart).

### Agent runs

For a hosted agent, pass the proxy in the run's browser settings:

<CodeGroup>
```python Python
run = client.runs.create(
    "Check the account dashboard",
    browser_settings={
        "customProxy": {
            "host": "proxy.example.com",
            "port": 8080,
            "username": "user",
            "password": "pass",
            "ignoreCertErrors": False,
        }
    },
)
```
```typescript TypeScript
const run = await client.runs.create({
  task: "Check the account dashboard",
  model: "gpt-5.6-luna",
  modelParams: { reasoning: { effort: "xhigh" } },
  browserSettings: {
    proxyCountryCode: "us",
    customProxy: {
      host: "proxy.example.com",
      port: 8080,
      username: "user",
      password: "pass",
      ignoreCertErrors: false,
    },
  },
});
```
</CodeGroup>

A custom proxy overrides `proxyCountryCode` and must be passed again when a
follow-up provisions a new browser. See the [Create run
reference](/cloud/api-v4/runs/create-run) for the complete settings object.

### Custom proxy fields

| Field | Required | Description |
| --- | --- | --- |
| `host` | Yes | Proxy host name, up to 255 characters. |
| `port` | Yes | Proxy port, 1 to 65535. |
| `username`, `password` | No | Proxy login. Send both or neither. The username can have up to 2048 characters and the password up to 8192. |
| `protocol` | No | `"http"` or `"https"` (TLS to the proxy itself). When you omit it, port 443 uses `https` and other ports use `http`. |
| `caBundle` | No | PEM certificates that the browser trusts in addition to the public roots, up to 16384 bytes. |
| `caBundleUrl` | No | An `https` URL of the PEM certificates, up to 2048 characters. Browser Use downloads it. Send `caBundle` or `caBundleUrl`, not both. |
| `ignoreCertErrors` | No | Turns off certificate checks for all sites. Use `caBundle` instead when you can. |

Use `caBundle` or `caBundleUrl` for a proxy that decrypts traffic with its own
CA, such as a card-vault proxy. The browser trusts that CA, and all other
sites keep full certificate checks. API responses never include the password,
`caBundle` or `caBundleUrl`.

## Change the proxy of a running browser

`PATCH /api/v4/browsers/{id}/proxy` changes the proxy of a running standalone
browser. The browser does not restart, so tabs, cookies and local storage
stay. `GET /api/v4/browsers/{id}/proxy` returns the current proxy. Both
endpoints need an API key with the `v4:browsers:create` scope (**Write** on
`browsers`), and they also exist in API v2 and v3.

| Body | Result |
| --- | --- |
| `{"mode": "managed", "country": "de"}` | Residential proxy in a country. |
| `{"rotate": true}` | New residential IP in the same country. |
| `{"target": "https://shop.example.com"}` | Residential proxy in the current country, with a new IP. |
| `{"mode": "direct"}` | No proxy. |
| `{"mode": "custom", "customProxy": {...}}` | Your proxy, with the fields above except `ignoreCertErrors`, which works only when the browser starts. |

For example, an agent can shop on the residential proxy and change to a
card-vault proxy at the payment step:

```bash curl
curl -X PATCH https://api.browser-use.com/api/v4/browsers/$BROWSER_ID/proxy \
  -H "X-Browser-Use-API-Key: $BROWSER_USE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "custom",
    "customProxy": {
      "host": "vault-proxy.example.com",
      "port": 443,
      "username": "YOUR_PROXY_USERNAME",
      "password": "YOUR_PROXY_PASSWORD",
      "caBundleUrl": "https://vault-proxy.example.com/ca.pem"
    }
  }'
```

After the payment, change back with `{"mode": "managed", "country": "us"}`,
or send a new `customProxy` for the next proxy login.

The response has the new state:

```json
{"mode": "custom", "country": null, "exitIp": null}
```

- `exitIp` is `null` for a custom proxy, because Browser Use does not send
  extra requests through your proxy.
- A change with a new CA takes about 5 seconds, while the browser loads the
  CA. Other changes take less than 1 second.
- Send one change at a time. A second change for the same browser returns
  `409` until the first one ends.
- Custom mode does not accept `country`, `target` or `rotate` (`422`).
- A browser on a custom proxy needs `mode` in each change. Else the change
  returns `409`.
- Custom mode is not available on the EU route (`422`).
- `409` also means the browser is stopped, belongs to an agent run, or has
  saved autofill passwords (custom mode only).

See the [Update browser proxy
reference](/cloud/api-v4/browsers/update-browser-proxy).

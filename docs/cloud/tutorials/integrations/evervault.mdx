[Evervault](https://evervault.com) keeps card data and credentials encrypted.
With Evervault in front of a Browser Use browser, the agent types stand-in
values, and Evervault swaps in the real ones only in the request to a website
you allow.

Browser Use connects to Evervault as a [custom proxy](/cloud/browser/proxies#custom-proxy) (an enterprise feature: contact sales@browser-use.com)
over TLS and trusts the Evervault CA, so Evervault can read that traffic. All
other sites keep full certificate checks.

## Browser Tokens for checkout and login forms

[Browser Tokens](https://docs.evervault.com/browser-tokens) are Evervault's
flow for agents. Evervault returns tokens that keep the format of the real
value: a Luhn-valid card number with the same length and BIN, a CVV with the
same number of digits. Checkout forms accept them like real values. When the
browser sends a token to a host you allowed, Evervault replaces it with the
real value on the way there.

<Note>
  Browser Tokens are in preview at Evervault. Ask Evervault support for access.
</Note>

### 1. Create tokens on your server

Call Evervault from your backend, never from the agent. `permissions` lists
the hosts that may receive the real values, for example the payment
processor's host:

```bash curl
curl https://api.evervault.com/browser-tokens \
  --user "$EVERVAULT_APP_ID:$EVERVAULT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "data": [
      {"id": "pan", "category": "card.number", "value": "ev:..."},
      {"id": "cvv", "category": "card.cvv", "value": "ev:..."}
    ],
    "permissions": [
      {"action": "decrypt", "target": "api.payments.example.com"}
    ],
    "ttl": 300
  }'
```

The response has the tokens in `data` and the proxy login in
`proxyConfiguration`:

```json
{
  "data": [
    {"id": "pan", "category": "card.number", "value": "4242424242424242"},
    {"id": "cvv", "category": "card.cvv", "value": "123"}
  ],
  "proxyConfiguration": {
    "hostname": "us-va.browser.relay.evervault.app",
    "port": 443,
    "username": "app_...",
    "password": "eyJ..."
  }
}
```

The proxy password expires with the tokens after `ttl` seconds. See
Evervault's [API reference](https://docs.evervault.com/api) for all fields,
including EU sessions (`eu-ie.browser.relay.evervault.app`).

### 2. Map `proxyConfiguration` to `customProxy`

| `proxyConfiguration` | `customProxy` |
| --- | --- |
| `hostname` | `host` |
| `port` | `port` |
| `username` | `username` |
| `password` | `password` |
| (none) | `caBundleUrl: "https://ca.evervault.com"` |

The port is 443, so `protocol` defaults to `https`. Do not use
`ignoreCertErrors`; it turns off certificate checks for every site.

### 3. Start the browser or run

A standalone browser:

```bash curl
curl https://api.browser-use.com/api/v4/browsers \
  -H "X-Browser-Use-API-Key: $BROWSER_USE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "customProxy": {
      "host": "us-va.browser.relay.evervault.app",
      "port": 443,
      "username": "PROXY_USERNAME",
      "password": "PROXY_PASSWORD",
      "caBundleUrl": "https://ca.evervault.com"
    }
  }'
```

For a hosted agent, pass the same object as `browserSettings.customProxy` on
`POST /api/v4/runs`, and give the agent the token values in the task, never
the real ones. Keep the run inside the token `ttl`.

### Use Browser Use residential IPs

By default, traffic leaves Evervault from Evervault's own IP addresses.
To use Browser Use residential IPs, add this `proxySettings` object to your
Evervault Browser Tokens request:

```json
{
  "proxySettings": {
    "type": "custom",
    "scheme": "https",
    "hostname": "proxy.browser-use.com",
    "port": 443,
    "username": "user-country-uk-session-00000000-0000-4000-8000-000000000001",
    "password": "YOUR_BROWSER_USE_API_KEY"
  }
}
```

The upstream proxy is `https://proxy.browser-use.com:443`.
The username format is `user[-country-XX][-session-ID]`; country and session
are optional. Replace the example session ID with your own proxy session ID.
The password is your Browser Use API key, not your Evervault API key.

Traffic follows this path: browser → Evervault → Browser Use residential
proxy → destination website.

Keep passing Evervault's returned `proxyConfiguration` to the Browser Use
`customProxy` fields above. Its password remains the Evervault proxy password;
the Browser Use API key above authenticates only the upstream connection.
See Evervault's [custom egress proxy settings](https://docs.evervault.com/browser-tokens#custom-egress-proxy)
for the request fields.

### 4. Switch only at the payment step (standalone browsers)

This step works only for standalone browsers you create with
`POST /api/v4/browsers`. Browsers that belong to an agent run cannot change
their proxy (`409`), so start a hosted run with its final
`browserSettings.customProxy`.

Save the `id` from the create-browser response as `BROWSER_ID`. Shop on the
residential proxy, create the tokens when the agent reaches the payment form,
then change the running browser to Evervault. Tabs and cookies stay:

```bash curl
curl -X PATCH https://api.browser-use.com/api/v4/browsers/$BROWSER_ID/proxy \
  -H "X-Browser-Use-API-Key: $BROWSER_USE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "custom",
    "customProxy": {
      "host": "us-va.browser.relay.evervault.app",
      "port": 443,
      "username": "PROXY_USERNAME",
      "password": "PROXY_PASSWORD",
      "caBundleUrl": "https://ca.evervault.com"
    }
  }'
```

The first change with the Evervault CA takes about 5 seconds. After the
payment, change back with `{"mode": "managed", "country": "us"}`. See
[Change the proxy of a running browser](/cloud/browser/proxies#change-the-proxy-of-a-running-browser)
for all rules and error codes.

## Relay for requests with `ev:` values

Evervault's [Relay forward proxy](https://docs.evervault.com/relay#forward-proxy-mode)
decrypts `ev:...` strings in requests to hosts set up as Relays in your
Evervault app. `ev:` strings do not look like card numbers, so checkout forms
usually reject them before any request is sent. Use Relay only when the page
sends the `ev:` values in a request itself, for example a script that calls
your payment API. For forms, use Browser Tokens.

| `customProxy` field | Value |
| --- | --- |
| `host` | `relay.evervault.com` |
| `port` | `443` |
| `username` | Your Evervault App ID |
| `password` | Your Evervault API key |
| `caBundleUrl` | `https://ca.evervault.com` |

## Good to know

- API responses never include the proxy password or the CA settings.
- `exitIp` is `null` while the browser is on Evervault.
- EU accounts can use Evervault too. Send the requests to
  `https://api.eu.browser-use.com/api/v4` with your EU API key, and use
  Evervault's EU proxy host. See [EU deployment](/cloud/eu-deployment).
- The proxy password can have up to 8192 characters.

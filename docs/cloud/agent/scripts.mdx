Deterministic rerun means you teach a Cloud agent a browser task once, and
every later run replays a saved script instead of exploring the site again.
The first run explores the site, writes a script, tests it, and saves it in its
[workspace](/cloud/agent/workspaces). Later runs with the same `workspace_id`
run that script against the live site and fix it if the site changed.

It suits work you repeat: scraping, monitoring, reports and checks.

## Measured: first run vs rerun

Same task text, same workspace, BU 4.0, 15 November 2026. Each number is the
median of 3 runs. Steps are model calls, counted from each run's event log.

| Task | One-off run (no script) | Rerun with saved script | Gain |
| --- | --- | --- | --- |
| Hacker News: 30 stories + each top comment | 13 steps, 55 s, \$0.097 LLM | 2 steps, 14 s, \$0.027 LLM | 6.5x fewer steps, 3.9x faster |
| YC Summer 2025: every company + founders | 25 steps, 130 s, \$0.184 LLM | 2 steps, 28 s, \$0.025 LLM | 12.5x fewer steps, 4.7x faster |
| GitHub trending: every repo page | 20 steps, 178 s, \$0.204 LLM | 2 steps, 30 s, \$0.026 LLM | 10x fewer steps, 5.9x faster |

- **One-off run:** the task without the reuse instructions, in a new workspace.
- **First run with reuse instructions** costs more than a one-off run because
  it also writes and tests the script: 15, 24 and 32 steps on the three tasks.
- **Total cost** (LLM + browser + proxy) fell 1.7-2.6x, not as much as the
  LLM cost. Every run still starts a browser, and pages fetched through the
  proxy still cost the same.
- **New input:** a rerun with a new input used the same script too: Hacker News
  page 2 and GitHub weekly trending took 2 steps each.

## Run it

Send the same task to the same workspace every time. Put the reuse
instructions at the end of the task. These are the exact instructions behind
the numbers above:

<CodeGroup>
```python Python
from browser_use_sdk.v4 import BrowserUse

TASK = (
    "Open https://github.com/trending?since={since} and, for every trending "
    "repository, open its repo page and get: owner/name, stars, forks, "
    "license, latest release tag and date (or none), and the top 3 "
    "contributors' usernames. Save the data to "
    "outputs/gh-trending-{since}.json and reply with the repo count and the "
    "first 3 rows."
    " I run this regularly with different inputs. If AGENTS.md lists a saved "
    "script for this task, run it directly (don't re-read or re-test it), "
    "then reply. Only if it is missing or fails: do the task, save a tested "
    "script under scripts/ that takes the input as an argument, and add one "
    "line to AGENTS.md with the exact command."
)

client = BrowserUse()
workspace = client.workspaces.create(name="github-trending")


def scrape(since: str):
    run = client.runs.create(
        TASK.format(since=since),
        model="bu-4.0",
        workspace_id=workspace.id,
    )
    return client.runs.wait_for_completion(run.id)


first = scrape("daily")  # explores the site, saves scripts/gh_trending.py
later = scrape("daily")  # runs the saved script
weekly = scrape("weekly")  # new input, same script
print(later.result, later.total_cost_usd)
```
```typescript TypeScript
import { BrowserUse } from "browser-use-sdk/v4";

const task = (since: string) =>
  `Open https://github.com/trending?since=${since} and, for every trending ` +
  "repository, open its repo page and get: owner/name, stars, forks, " +
  "license, latest release tag and date (or none), and the top 3 " +
  "contributors' usernames. Save the data to " +
  `outputs/gh-trending-${since}.json and reply with the repo count and the ` +
  "first 3 rows." +
  " I run this regularly with different inputs. If AGENTS.md lists a saved " +
  "script for this task, run it directly (don't re-read or re-test it), " +
  "then reply. Only if it is missing or fails: do the task, save a tested " +
  "script under scripts/ that takes the input as an argument, and add one " +
  "line to AGENTS.md with the exact command.";

const client = new BrowserUse();
const workspace = await client.workspaces.create({ name: "github-trending" });

async function scrape(since: string) {
  const run = await client.runs.create({
    task: task(since),
    model: "bu-4.0",
    workspaceId: workspace.id,
  });
  return client.runs.waitForCompletion(run.id);
}

const first = await scrape("daily"); // explores the site, saves scripts/gh_trending.py
const later = await scrape("daily"); // runs the saved script
const weekly = await scrape("weekly"); // new input, same script
console.log(later.result, later.totalCostUsd);
```
</CodeGroup>

Keep the workspace ID. A rerun can come from another process days later: pass
the same `workspace_id` / `workspaceId` and the same task.

## How it works

1. **The first run** explores the site like any agent run. Then it writes a
   script under `scripts/`, runs it to check the output, and adds one line to
   `AGENTS.md` with the exact command.
2. **The workspace keeps both files.** Every run in that workspace starts with
   the workspace files restored, and every agent reads `AGENTS.md` first.
3. **A rerun** sees the command in `AGENTS.md`, runs the script, and replies.
   That is 2 model calls: one to run the script, one to answer.
4. **If the script fails**, the agent sees the error, fixes the script, saves
   it, and replies. In our YC test, a new input (Spring 2025) hit a company
   with no one-liner. The agent patched the script and reran it: 17 steps,
   still fewer than a run from scratch, and later runs reuse the fixed script.

The script fetches the live site on every run. It is not a cached answer.

## Tips for the biggest savings

- **Write data to a file in `outputs/`** and reply with a short summary. A long
  JSON reply costs model time on every run: in our first tests, typing 150
  rows back took about 57 s of a rerun.
- **Ask for the input as an argument** ("takes the input as an argument") so a
  new page, date or keyword reuses the same script.
- **Save scripts under `scripts/`.** You can list and download them, and they
  persist across runs.
- **Tell the agent not to re-read or re-test the script.** Without that line,
  reruns took 7-11 steps instead of 2 because the agent checked its work.
- **Use one workspace per job.** Two jobs that share a workspace share
  `AGENTS.md`, which makes it harder for the agent to pick the right script.

## Download the script

The script is a normal file. Run it yourself, review it, or keep it in git:

<CodeGroup>
```python Python
files = client.workspaces.files(workspace.id, prefix="scripts/", include_urls=True)
for f in files.files:
    print(f.path, f.url)
```
```typescript TypeScript
const files = await client.workspaces.files(workspace.id, {
  prefix: "scripts/",
  includeUrls: true,
});
for (const f of files.files) console.log(f.path, f.url);
```
</CodeGroup>

## Workspace or session?

- Pass `workspace_id` / `workspaceId` for a new conversation with the same
  files. Use this for reruns: each run starts clean and reads `AGENTS.md`.
- Pass `session_id` / `sessionId` to continue the old conversation and its
  workspace. Cloud can also reuse that session's browser while it is still
  alive.

## Coming from V3 `cache_script`?

V3 hashed a task template with `@{{params}}` and ran a cached script on the
server with no model call. In V4 the agent itself writes, runs and repairs the
script, so you get the same reuse plus repair when a site changes. Each rerun
still makes about 2 model calls (\$0.02-0.03 in the tests above). The V3
fields stay in the [V3 API reference](/cloud/api-v3/sessions/create-session).
